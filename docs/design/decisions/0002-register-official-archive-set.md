# ADR-0002: 归档改为「官方归档集合登记 + 物理搬移」两步

状态:accepted(2026-10-10,取代 overview 旧版「不改 workspace 注册表」的非目标)

## 背景

0.1.x 时代验证过的假设是「物理移走目录后 persistence 自然看不到,悬空条目被 UI 容忍」——当时 Web 侧栏是平面列表,目录扫描即列表,搬走 = 行消失。

0.2.0 的三个变化打破了这个假设:

1. 子代理列表行改为由**父会话日志的 `subagent/catalog` 事件**驱动(session-controller 的 `subagentCatalog` 投影;无 summary 的行也合成显示)——事件随父会话持久存在,搬目录不影响行渲染;
2. 新增**工作区侧栏树**与头部子代理计数,悬空行变得更显眼;
3. 新增**持久投影缓存**(`storages/session_projcache`),逐会话记录无任何清理机制,已移走的会话缓存永久残留。

实际症状:已归档子 agent 在头部下拉里仍显示「可继续」,点击因数据已移走而 404。

同时 0.2.0 官方提供了完整的归档机制:`workspaceRegistry` 的持久归档 id 集合(`storages/workspace.json`)——UI 按集合过滤、归档视图可恢复、`archived-session-gate` 阻止归档会话跑模型步进。

## 备选

- **A. 维持纯搬移**:不改。悬空行继续误导(可继续/有标题),无恢复语义。否决。
- **B. 改用官方归档、放弃搬移**:语义最正,但放弃插件的核心价值——目录搬移才是真正减小 `session.list` 载荷与磁盘占用的手段(官方归档不移动数据)。否决。
- **C. 登记官方集合 + 保留搬移**(采用):官方语义接管(过滤/闸门/恢复),物理搬移保留减负价值。
- **D. 重写父会话日志移除 catalog 事件**:日志只追加、无移除协议,伪造事件需发明官方不存在的版本,污染用户数据。否决。

## 决策

采用 C。归档流程变为:复查 → `archiveSession(id)`(数据在场,通过存在性检查;活动拒绝则跳过候选)→ `rename` → 删除 projcache 记录。删除模式不登记。另有一次性回填(manifest → 搬回 → 登记 → 搬回)消化历史存量。

projcache 记录用**文件级删除**(per-record 布局,单记录单文件,官方读语义把缺失按缺席处理):`DomainFacility.open` 对已打开域强制单开(already-open),插件拿不到进程内句柄,域 API 不可用;文件删除后域内存残影到重启为止,但归档会话不再被列出,残影无读取路径。

## 后果

- 正面:官方 UI/闸门/恢复语义全部生效;缓存不再残留死数据;历史存量可回填。
- 残留:父会话头部下拉仍列出已归档子 agent(平台限制,ADR-0002 不解决,0.2.0-rc.2 无解);下拉行点击打不开的观感只能靠官方后续(如 ui-subagent 读归档集合)消除。
- 回滚语义增强:恢复 = 目录移回 + 官方集合取消登记(GUI 归档视图自带恢复按钮)。
- `workspaceRegistry` 缺失的 profile 自动退化为纯搬移(计数器 `archivedSetUnavailable` 上报)。
