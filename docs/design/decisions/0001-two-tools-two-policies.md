# ADR-0001:两个工具、两套判据(权限凭证分级)

状态:accepted(2026-08-26)

## 背景

清理子 agent 会话的请求有两个天然不同的来源:会话自己(长期任务收尾,清自己的后代)和运维侧(跨 workspace 大扫除,清"别人"的记录)。安全判据该多严,取决于"谁授权这次清理"。

## 备选

1. **单工具 + scope 参数**:一个入口,参数选择作用域,判据统一从严(进程启动 + 24h)
2. **单工具 + 判据随 scope 切换**:同上,但 scope=self 时放宽
3. **两个工具、两套判据**(采纳)

## 决策

拆成 `subagent_cleanup`(自清)与 `subagent_cleanup_global`(运维),共享规划-执行引擎,判据按候选的**权限凭证**分级:

- 自清/点名:枚举确认"是调用方的后代 + 官方状态非 running"本身就是授权 → 只留写入缓冲(inactive 30s / running 10min),无闲置小时门槛。否则长期任务收尾时孩子都是几小时前结算的,24h 门槛会挡掉全部目标,工具形同虚设
- 大扫除:动的是未知归属的记录 → 严格双门(当前进程启动后从未写入 + 闲置 ≥ 24h),对应 2026-08-26 手工验证过的安全边界

## 后果

- 正面:两个场景各自拿到"刚好够用"的判据;description/引导段可分别写清触发条件,模型路由更准
- 正面:两工具共享 `planSessionActions` 纯函数与执行引擎,判据矩阵有单测锁定
- 代价:模型需要理解两个相近工具的分工(靠 description 的"何时用/何时不用"与引导段解决)
- 已知取舍:`activity: running` 包含"已结算但记录驻留内存"的子 agent,靠 10min 静默而非精确结算状态区分——官方枚举不暴露结算态,这是可得数据内的最稳近似
